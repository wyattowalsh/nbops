# Accessibility UX plan

## Target and policy

Target WCAG 2.2 Level AA for both the notebook dashboard and docs site. Automated tooling is necessary but insufficient. Release evidence includes keyboard, screen-reader, zoom/reflow, contrast, reduced-motion, and chart/table parity checks.

Known exceptions must state the affected criterion/user, exact surface, workaround, owner, and repair milestone. “Third-party chart library” is not a blanket exception.

## Semantic architecture

```text
region: colab-observer dashboard
  heading level 2: run name and status
  status: sampler/capability summary
  navigation: dashboard views
  main:
    region: current metrics
    region: selected visualization
      heading
      textual interpretation
      chart (supplemental)
      accessible data table
    region: diagnostics
  complementary: export/status details
```

The embedding notebook supplies the outer document. The dashboard begins at an appropriate heading level and does not create a second document-level `<h1>` without context.

## Keyboard contract

| Action | Expected path |
|---|---|
| Enter dashboard | Focus visible on first meaningful control or skip link |
| Skip repeated overview | “Skip to diagnostics/data table” links |
| Change view | Arrow-key tab pattern or standard select/menu behavior |
| Select range/series | Native button/checkbox/select semantics |
| Inspect exact point | Focusable point-detail list or table; not pointer-only |
| Sort process table | Focusable button in header with `aria-sort` |
| Open/close diagnostic | Button; dialog/panel focus managed and returned |
| Pause live view | Toggle button with state and explanatory text |
| Export | Button opens controlled panel; Escape/close returns focus |
| Leave widget | Normal tab progression; no trap |

Never overload arrow keys on a custom control without implementing the relevant WAI-ARIA APG interaction pattern and documenting it.

## Focus

- Use a high-contrast, non-clipped focus indicator with at least the WCAG 2.2 focus-appearance intent.
- Do not remove outlines globally.
- Preserve focus through data refreshes; never recreate focused controls on each sample.
- Do not move focus when diagnostics appear.
- Dialogs and drawers use initial focus on title or first safe control and restore focus to the opener.
- Sticky headers and Colab output clipping must not obscure the focused target.

## Live regions

| Update | Announcement policy |
|---|---|
| Every metric sample | None |
| Run starts/stops | Polite concise status |
| New medium warning | Polite, deduplicated |
| New critical storage/memory risk | Assertive only when immediate user action may prevent data loss |
| Warning remains active | No repeated sample-by-sample announcement |
| Export completed/failed | Polite status with path/recovery text |
| Capability provider changes | Polite if user-impacting |

The live-view pause also pauses non-critical announcements.

## Charts and data equivalence

Every chart ships with:

1. title and selected time range;
2. short natural-language summary of current value, extrema/trend where meaningful, and gaps;
3. series/units legend expressed in text;
4. semantic table containing timestamp/bin and values;
5. CSV export for the same selection;
6. non-color series encodings;
7. an accessible exact-value path that does not require dragging or hover.

Chart ARIA generated by a library may enhance orientation but does not replace the table. Decorative chart internals may be hidden from assistive technology when the concise summary/table provide better navigation.

## Visual criteria

- Body and control text meet AA contrast; non-text status/focus/graphical controls meet applicable contrast.
- Text supports 200% zoom and responsive reflow without loss of content/function.
- Control targets satisfy WCAG 2.2 target-size requirements or documented equivalent spacing exceptions.
- Information is not encoded by color alone.
- High-contrast mode uses native/system color compatibility where possible.
- Text in charts is not the only occurrence of labels or values.
- Do not use tiny low-contrast sparkline-only trend communication.

## Motion and timing

- Honor `prefers-reduced-motion` from first render.
- Avoid auto-scrolling, pulsing warnings, sweeping gauges, and unnecessary count animations.
- Animate chart transitions only when motion is allowed, bounded, and informative.
- Provide live pause without stopping collection.
- No time limit is imposed for reading diagnostics or export settings.

## Forms, tables, and messages

- Labels remain visible; placeholders are examples, not labels.
- Validation errors identify the field, cause, and correction.
- Table captions name data and time range.
- Sort state and units are available in headers.
- Empty, stale, partial, and unavailable states are textually distinct.
- “Copy” and “download/export” controls announce success/failure without relying on a toast alone.

## Colab embedding risks

| Risk | Mitigation |
|---|---|
| Output frame sizing/clipping | Content-driven height, bounded internal regions, resize tests |
| Custom widget manager unavailable | Static semantic fallback |
| Focus crossing iframe/widget boundary | Explicit first/last focus behavior and no trap |
| Browser zoom/narrow cell | Responsive reflow and 200% tests |
| Theme mismatch with notebook | Semantic tokens and explicit theme selector/system mode |
| Widget reconnect rerender | Stable keys and focus preservation |

## Validation matrix

### Automated

- DOM accessibility engine on representative states.
- Unit tests for names, roles, states, focus restoration, announcements, and table parity.
- Contrast token tests and reduced-motion snapshots.
- Docs build checks for headings, alt text, links, labels, and code-copy controls.

### Manual

- Keyboard-only complete user journey.
- Screen-reader checks using at least one Chromium-based and one platform-native combination where feasible.
- 200% and 400% zoom/reflow spot checks.
- Windows high-contrast/forced-colors or equivalent.
- Reduced-motion behavior.
- Touch/pointer target checks.
- Static fallback and HTML report.

## Accessibility Definition of Done

- No critical/serious automated finding remains unexplained.
- All primary tasks complete keyboard-only.
- Focus remains visible and stable during updates.
- No chart lacks summary/table/export parity.
- New diagnostics are deduplicated and announcement policy is verified.
- Docs and dashboard pass the shared manual checklist.
- Known limitations are published, actionable, and not concealed by a generic conformance claim.
