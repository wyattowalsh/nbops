# Glossary

| Term | Meaning |
|---|---|
| OpenSpec | Spec-driven workflow where accepted behavior and proposed changes are captured as artifacts. |
| Delta spec | Proposed requirement changes under ADDED, MODIFIED, and REMOVED sections. |
| AGENTS.md | Codex-readable durable project guidance. |
| Goal | Codex finish-line contract with verification and stop conditions. |
| PLANS | Living execution plan for long-running work. |
| Obsidian vault | Folder of Markdown notes plus optional `.obsidian` settings. |
| Bases | Obsidian core feature for database-like views over note properties. |
| Plugin profile | Bounded set of approved community-plugin IDs with setup, risk, and fallback rules. |

| Runtime profile | Versioned bounded evidence describing provider, frontend, kernel, scope, storage, display, support, conflicts, and limitations. |
| Measurement scope | The process, process tree, kernel, container, server, host, or unknown boundary to which evidence applies. |
| Support tier | Evidence-backed validated, preview, experimental, unverified, or unsupported status for a stated platform/scope/transport. |
| Storage profile | A classified output location with role, persistence expectation, performance posture, confidence, and safety limitations. |
